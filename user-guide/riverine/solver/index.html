    Transport Solver¶

    ClearWater-Riverine solves the two-dimensional, depth-averaged advection-diffusion equation on the HEC-RAS 2D unstructured mesh using an implicit finite volume scheme. This page describes the governing equation, the spatial and temporal discretization, the sparse linear solve, and the per-timestep update procedure. The solver is implemented in src/clearwater_riverine/transport.py and src/clearwater_riverine/linalg.py.

    Governing Equation¶

    For a scalar constituent with concentration C, cell volume V, face flow Q, and diffusion coefficient D, the depth-averaged transport equation integrated over one cell is:

    \[ \frac{\partial (V C)}{\partial t} + \sum_{\text{faces}} (Q C)_{\text{upwind}} - \sum_{\text{faces}} D A_f \frac{C_{\text{nbr}} - C}{L_f} = 0 \]

    where A_f is the vertical area of the face, L_f is the distance between the centers of the two cells sharing the face, and the subscript upwind indicates that the advected concentration is taken from the cell on the upwind side of the face.

    Finite Volume Discretization¶

    ClearWater-Riverine integrates the transport equation over each cell in the mesh. The spatial operator assembles contributions from every edge.

    Advection¶

    The advection term uses a first-order upwind scheme. For each edge connecting cell i and cell j with face flow Q_ij:

    • If Q_ij > 0 (flow from i to j), the advected concentration is C_i.
    • If Q_ij < 0 (flow from j to i), the advected concentration is C_j.

    The upwind choice is stored as the ADVECTION_COEFFICIENT variable on the mesh, with sign indicating the flow direction. Upwinding ensures monotonicity but introduces numerical diffusion proportional to the cell size and the flow speed.

    Diffusion¶

    The diffusion term uses a standard two-point flux approximation. For each edge between cells i and j:

    \[ F_{\text{diff}} = D A_f \frac{C_j - C_i}{L_f} \]

    ClearWater-Riverine computes D A_f / L_f once during mesh preparation and stores the result as COEFFICIENT_TO_DIFFUSION_TERM on the mesh. The diffusion coefficient D is the scalar diffusion_coefficient from the configuration.

    Volume Change¶

    The time derivative partial (V C) / partial t is expanded to account for the time-varying cell volume supplied by HEC-RAS. The framework stores VOLUME at every timestep and CHANGE_IN_TIME as the timestep duration. Volume changes enter the discretization as contributions to both the diagonal of the left-hand side matrix and the right-hand side vector.

    Implicit Time Stepping¶

    ClearWater-Riverine uses a fully implicit (backward Euler) time discretization. At each timestep n, the framework assembles and solves:

    \[ A\, C^{n+1} = b^n \]

    where A is a sparse matrix of size (nreal + 1, nreal + 1) built from the advection and diffusion coefficients and the current cell volumes, and b^n is a vector built from the concentrations at timestep n, boundary inflows at timestep n+1, and the previous cell volumes.

    The implicit scheme is unconditionally stable with respect to advection and diffusion. The timestep is inherited from the HEC-RAS output, so the modeler controls stability and accuracy by choosing the HEC-RAS output interval rather than a separate transport timestep.

    Sparse Linear Solve¶

    ClearWater-Riverine builds A as a compressed sparse row (CSR) matrix using scipy.sparse.csr_matrix and solves the system with scipy.sparse.linalg.spsolve. The framework constructs the matrix from three parallel arrays.

    Array Contents
    lhs.coef Matrix coefficients (advection, diffusion, and volume terms).
    lhs.rows Row indices for each coefficient.
    lhs.cols Column indices for each coefficient.

    The LHS class in src/clearwater_riverine/linalg.py exposes an update_values(mesh, t) method that refreshes the three arrays using the flow field at timestep t. Because the matrix depends only on flow and geometry, ClearWater-Riverine assembles A once per timestep and reuses it across all constituents.

    Each constituent owns its own right-hand side vector through the RHS class. The right-hand side is updated per constituent per timestep via b.update_values(solution, mesh, t, name).

    Ghost Cells¶

    HEC-RAS boundary faces connect real cells to ghost cells that live outside the domain. ClearWater-Riverine indexes ghost cells after the real cells, so the total cell count is nreal + nghost. The matrix A has dimension (nreal + 1, nreal + 1) and represents the real cells plus one slot used to apply boundary concentrations. The additional slot receives concentration values taken directly from the aligned boundary condition time series, so boundary inflows appear in A x = b as known forcing rather than as unknowns.

    Per-Timestep Update Procedure¶

    The update method on the ClearwaterRiverine class advances the solution one timestep. The procedure is:

    1. Refresh the left-hand side arrays for the current timestep with self.lhs.update_values(mesh, time_step).
    2. Build A = csr_matrix(...) with shape (nreal + 1, nreal + 1).
    3. For each constituent: a. Optionally override the current concentration with a user-supplied value passed via the update_concentration dictionary. This is the hook used by the ClearWater Modules coupling pattern to inject updated state between transport steps. b. Refresh the right-hand side vector using constituent.b.update_values(...). c. Solve x = spsolve(A, constituent.b.vals). d. Write x into the mesh at time_step + 1. e. Overwrite cells that carry nonzero boundary condition inputs with the boundary concentration. f. Compute advective, diffusive, and total mass flux across every edge and store the values on the mesh.
    4. Increment self.time_step by one.

    The mass flux recovery in step 3f reconstructs edge-wise fluxes using the newly solved concentrations, the ADVECTION_COEFFICIENT field, and the COEFFICIENT_TO_DIFFUSION_TERM field. These fluxes are used by the post-processing utilities; see Post-Processing.

    Running to Completion¶

    A typical simulation loops update across the HEC-RAS time axis and then calls finalize to set plot value ranges and optionally save the mesh.

    from clearwater_riverine import ClearwaterRiverine

simulation = ClearwaterRiverine(
    config_filepath="configs/ohio_river.yml",
    verbose=True,
)

for _ in range(len(simulation.mesh.time) - 1):
    simulation.update()

simulation.finalize(
    save=True,
    output_filepath="results/ohio_river.zarr",
)

    The finalize call writes the ClearWater-Riverine mesh to Zarr and the boundary data to a companion CSV. The saved mesh can be reloaded later for post-processing and plotting by passing mesh_file_path to the ClearwaterRiverine constructor.

    Numerical Considerations¶

    • Mass conservation. The implicit finite volume scheme is mass-conservative to the accuracy of the linear solve. Residual mass balance error reported by the post-processing utilities typically reflects accumulated floating point error and any mismatch between HEC-RAS face flows and volume changes.
    • Numerical diffusion. First-order upwinding introduces artificial diffusion. If the physical diffusion coefficient is small relative to numerical diffusion, the transport solution will appear more diffuse than the underlying problem warrants. Refining the mesh reduces numerical diffusion.
    • Negative concentrations. The implicit upwind scheme is monotone in the absence of steep boundary transients. If negative concentrations appear, check for sharp boundary condition discontinuities and for HEC-RAS cells with very small or zero volume.
