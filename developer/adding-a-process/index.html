    Adding a New Process¶

    This page describes the end-to-end recipe for adding a new water quality process to ClearWater v2. It assumes you have read the Architecture Walkthrough and understand the Process lifecycle, the VariableRegistry, and the Model orchestrator.

    The recipe has five steps:

    1. Create a Process subclass in src/clearwater_modules_v2/processes/<name>.py.
    2. Register the class with ProcessFactory via from_config.
    3. Implement per-term rate helper methods (one per source or sink) and compose them in run.
    4. Add the new class to the RUN_ORDER list in src/clearwater_modules_v2/processes/__init__.py.
    5. Add a v1-parity test under tests/.

    This page works through a complete, compilable example: a simple first-order decay tracer. Real Nutrient Simulation Module 1 (NSM1) derivatives are more complex, but the structure is identical. Use the example as a starting template and refer to temperature.py, floating_algae.py, and nitrogen.py for richer patterns.

    Step 1. Create the Process Subclass¶

    Create src/clearwater_modules_v2/processes/tracer.py with the following skeleton.

    """First-order decay tracer process."""

from datetime import datetime, timedelta
from typing import TYPE_CHECKING

import numpy as np
import xarray as xr

from clearwater_data.custom_types import ArrayLike
from clearwater_data.variables import VariableRegistry

from clearwater_modules_v2.processes.base import Process, ProcessFactory
from clearwater_modules_v2.utils.conversions import arrhenius_correction

if TYPE_CHECKING:
    from clearwater_modules_v2.model import Model


class Tracer(Process):
    """First-order decay tracer with temperature-corrected rate.

    The process integrates a single state variable, ``tracer``, with a
    first-order loss term whose rate is Arrhenius-corrected from a
    reference temperature of 20 degrees Celsius.

    Parameters
    ----------
    time_step : timedelta
        Process time step.
    decay_rate_20 : float
        First-order decay rate at 20 degrees Celsius, in day-1.
    decay_theta : float
        Arrhenius temperature correction factor (dimensionless).
    """

    variables = [
        "tracer",
        "water_temperature",
    ]

    def __init__(
        self,
        time_step: timedelta = timedelta(minutes=5),
        decay_rate_20: float = 0.1,
        decay_theta: float = 1.047,
    ) -> None:
        self.decay_rate_20 = decay_rate_20
        self.decay_theta = decay_theta
        Process.__init__(self, time_step)

    The variables class attribute lists every registry key the process reads or writes. The Model uses this list to validate the registry before the simulation starts. The __init__ method stores kinetic parameters as instance attributes and calls Process.__init__ with the time_step.

    Accept ArrayLike rather than float

    When a parameter may vary in space (for example, a settling velocity that differs per-cell), declare it as ArrayLike rather than float. Scalars and xarray DataArray objects both satisfy the type, and downstream arithmetic broadcasts naturally.

    Step 2. Register with ProcessFactory¶

    Add a from_config classmethod decorated with ProcessFactory.register directly after __init__.

        @ProcessFactory.register("tracer")
    @staticmethod
    def from_config(
        config: dict, variable_registry: VariableRegistry
    ) -> "Tracer":
        return Tracer(**config)

    The short name passed to register is the identifier used in the YAML configuration. After registration, a YAML block like the following will construct the process:

    processes:
  - name: tracer
    config:
      decay_rate_20: 0.2
      decay_theta: 1.05
      time_step: 300

    Step 3. Implement init_process¶

    Use init_process to inspect the model for optional coupling partners. For the decay tracer the hook is minimal, but it illustrates the pattern for richer processes.

        def init_process(self, model: "Model", registry: VariableRegistry) -> None:
        """Detect optional coupling partners before the time loop starts."""
        self.use_temperature_correction = model.has_process("Temperature")

    For processes that couple to others (for example, the nitrogen process reading the floating algae respiration rate), init_process is where you resolve the sibling process handle:

    if model.has_process("FloatingAlgae"):
    self.floating_algae = model.get_process("FloatingAlgae")

    Step 4. Implement Per-Term Rate Methods¶

    Break the derivative into one public method per source or sink term. This pattern, used by FloatingAlgae and Nitrogen, lets other processes pull individual terms as coupling inputs without recomputing the full derivative.

        def rate_decay(
        self,
        tracer: ArrayLike,
        water_temperature: ArrayLike,
    ) -> ArrayLike:
        """Compute the first-order decay rate.

        Parameters
        ----------
        tracer : ArrayLike
            Tracer concentration in mg L-1.
        water_temperature : ArrayLike
            Water temperature in degrees Celsius.

        Returns
        -------
        ArrayLike
            Decay rate in mg L-1 day-1.
        """
        k = arrhenius_correction(
            water_temperature,
            self.decay_rate_20,
            self.decay_theta,
        )
        return k * tracer

    The arrhenius_correction helper in clearwater_modules_v2/utils/conversions.py centralizes the rc20 * theta^(TwaterC - 20) pattern used across the framework. Always prefer the helper over inlining the formula so that future changes (for example, adding input validation on theta) apply everywhere.

    Step 5. Implement the run Method¶

    The run method pulls inputs from the registry, composes the rate terms, integrates forward one step, clips negative concentrations, and writes the result back.

        def run(self, time: datetime, registry: VariableRegistry) -> None:
        """Advance the tracer one time step."""
        tracer = registry.get_at_time("tracer", time)
        water_temperature = registry.get_at_time("water_temperature", time)

        loss = self.rate_decay(tracer, water_temperature)

        # Explicit Euler step. Rate is in day-1; convert dt to days.
        dt_days = self.time_step.total_seconds() / 86400.0
        new_tracer = tracer - loss * dt_days

        # Clip negative concentrations that can arise from a large dt.
        new_tracer = xr.where(new_tracer < 0, 0, new_tracer)

        # Persist the updated state. THIS IS REQUIRED.
        registry.set_at_time("tracer", new_tracer, time)

    Persist every state variable you update

    The single most common mistake in early v2 work is computing an updated value and failing to call registry.set_at_time. The update is silently dropped, and downstream processes see stale state. Every run method must end with a set_at_time call for every variable it updates.

    Do not test for NaN with equality

    xr.where(x == np.nan, 0, x) is always False under IEEE 754. Use xr.where(x.isnull(), 0, x) or xr.where(np.isnan(x), 0, x) to substitute a fallback value for missing data.

    Step 6. Register the Process in RUN_ORDER¶

    Open src/clearwater_modules_v2/processes/__init__.py and add the new class to the RUN_ORDER list. Order matters: processes that consume outputs of another process must appear after their dependency.

    from clearwater_modules_v2.processes.riverine import Riverine
from clearwater_modules_v2.processes.temperature import Temperature
from clearwater_modules_v2.processes.benthic_algae import BenthicAlgae
from clearwater_modules_v2.processes.floating_algae import FloatingAlgae
from clearwater_modules_v2.processes.nitrogen import Nitrogen
from clearwater_modules_v2.processes.tracer import Tracer

RUN_ORDER = [
    Riverine,
    Temperature,
    BenthicAlgae,
    FloatingAlgae,
    Nitrogen,
    Tracer,
]

    Step 7. Add a v1-Parity Test¶

    For any process that has a v1 reference implementation, add a v1-parity test that runs identical inputs through both and asserts the outputs agree within tolerance. Use tests/test_5_tsm_calculations_v2.py as a template.

    # tests/test_5_tracer_calculations_v2.py
from datetime import datetime, timedelta

import numpy as np
import pytest
import xarray as xr

from clearwater_modules.<v1_path> import tracer_v1_derivative
from clearwater_modules_v2.processes.tracer import Tracer


@pytest.fixture
def inputs():
    return {
        "tracer": xr.DataArray(np.array([1.0, 0.5, 2.0])),
        "water_temperature": xr.DataArray(np.array([15.0, 20.0, 25.0])),
    }


def test_tracer_v1_parity(inputs):
    """v2 Tracer matches the v1 first-order decay reference implementation."""
    process = Tracer(
        time_step=timedelta(minutes=5),
        decay_rate_20=0.1,
        decay_theta=1.047,
    )
    v2_rate = process.rate_decay(
        inputs["tracer"], inputs["water_temperature"]
    )
    v1_rate = tracer_v1_derivative(
        inputs["tracer"].values,
        inputs["water_temperature"].values,
        decay_rate_20=0.1,
        decay_theta=1.047,
    )
    np.testing.assert_allclose(v2_rate.values, v1_rate, rtol=1e-6)

    Add unit tests that cover each rate_* method in isolation as well. See the Testing Strategy page for the full test taxonomy.

    Complete Example¶

    The full tracer.py file, assembled from the snippets above, is a runnable starting template for new processes:

    """First-order decay tracer process."""

from datetime import datetime, timedelta
from typing import TYPE_CHECKING

import numpy as np
import xarray as xr

from clearwater_data.custom_types import ArrayLike
from clearwater_data.variables import VariableRegistry

from clearwater_modules_v2.processes.base import Process, ProcessFactory
from clearwater_modules_v2.utils.conversions import arrhenius_correction

if TYPE_CHECKING:
    from clearwater_modules_v2.model import Model


class Tracer(Process):
    """First-order decay tracer with temperature-corrected rate."""

    variables = ["tracer", "water_temperature"]

    def __init__(
        self,
        time_step: timedelta = timedelta(minutes=5),
        decay_rate_20: float = 0.1,
        decay_theta: float = 1.047,
    ) -> None:
        self.decay_rate_20 = decay_rate_20
        self.decay_theta = decay_theta
        Process.__init__(self, time_step)

    @ProcessFactory.register("tracer")
    @staticmethod
    def from_config(
        config: dict, variable_registry: VariableRegistry
    ) -> "Tracer":
        return Tracer(**config)

    def init_process(self, model: "Model", registry: VariableRegistry) -> None:
        self.use_temperature_correction = model.has_process("Temperature")

    def rate_decay(
        self,
        tracer: ArrayLike,
        water_temperature: ArrayLike,
    ) -> ArrayLike:
        """Compute the first-order decay rate in mg L-1 day-1."""
        k = arrhenius_correction(
            water_temperature,
            self.decay_rate_20,
            self.decay_theta,
        )
        return k * tracer

    def run(self, time: datetime, registry: VariableRegistry) -> None:
        tracer = registry.get_at_time("tracer", time)
        water_temperature = registry.get_at_time("water_temperature", time)

        loss = self.rate_decay(tracer, water_temperature)

        dt_days = self.time_step.total_seconds() / 86400.0
        new_tracer = tracer - loss * dt_days
        new_tracer = xr.where(new_tracer < 0, 0, new_tracer)

        registry.set_at_time("tracer", new_tracer, time)

    Checklist Before Opening a Pull Request¶

    • [ ] Process subclass lives in src/clearwater_modules_v2/processes/<name>.py.
    • [ ] variables class attribute lists every registry key read or written.
    • [ ] __init__ accepts all kinetic parameters with sensible defaults and calls Process.__init__ with the time_step.
    • [ ] from_config is decorated with @ProcessFactory.register("<name>").
    • [ ] init_process resolves optional couplings via model.has_process and model.get_process.
    • [ ] Each source and sink term has its own public rate_* method with a NumPy-style docstring.
    • [ ] run calls registry.set_at_time for every state variable it updates.
    • [ ] Temperature-dependent rates use arrhenius_correction from clearwater_modules_v2/utils/conversions.py.
    • [ ] The process is added to RUN_ORDER in process dependency order.
    • [ ] Unit tests cover each rate_* method and the integration step in run.
    • [ ] A v1-parity test (where applicable) asserts v2 matches v1 within a documented tolerance.

    See the Contributing Guidelines for the pull request workflow and Testing Strategy for the full test taxonomy.
